<objective>
## Phase Goal

**As a** 维护者（lab maintainer）, **I want to** 推送代码到 GitHub 后 Actions 自动完成完整构建（含 jekyll-scholar）并发布上线，本地与 CI 构建一致, **so that** 内容更新推送即自动发布，无需任何手工发布步骤。

## Plan 04 — 原地接管：D-15①~④（push → 默认分支 → build_type → 验证模式）

Purpose: 执行用户锁定的渐进式接管序列（D-15）的前四步，**全程无 force push、零停机**：① push main（新增分支，master 原封不动）→ ② PATCH default_branch=main → ③ PUT pages build_type=workflow（旧站快照继续服务）→ ④ dispatch 验证模式人工确认产物。步骤顺序不可重排（研究证实的功能硬约束：dispatch 只认默认分支上的 workflow；deploy-pages 在 build_type 未切前会失败）。本 Plan 是 DEPLOY-02 的主证现场——Ruby 4.0.6 + Jekyll 4.4.1 组合首次在 Linux runner 上验证（已知风险：该组合此前仅 arm64 macOS 实测；若失败按禁止项回报用户，不擅自改版本）。

Output: 远端分支/配置三处切换完成 + 两次绿色构建（push 触发 + dispatch 验证模式）+ deploy 全程未放行（闸门交给 Plan 05）。
</objective>
